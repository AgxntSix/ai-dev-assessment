# AgxntSix AI developer assessment

At the start of every session, before any other work, read `BRIEF.md` and `RULES.md`, then show the user a short summary of `BRIEF.md`: the scene, their role, what's at stake, the constraints and the current ticket in `TICKETS/`.

When a ticket is done, keep the flow going without waiting to be told:
1. Commit with the ticket ID at the start of the message, and push.
2. Run `bun run submit`. Ask the user for their own answers to its decision questions and follow-ups; never write those answers yourself.
3. When the next ticket lands in `TICKETS/`, show the user a short summary of it and start on it.
